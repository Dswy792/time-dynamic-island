# 灵动岛 v5.2.3 架构说明

> 面向开发者的实现说明：模块边界、数据流、消息提醒管线、渲染与动画管线、持久化方案和关键设计决策。
> 用户使用文档见 [README](../README.md)；最初的项目计划（历史文档）见 [灵动岛实现计划](灵动岛实现计划.md)。

---

## 1. 设计目标与原则

1. **零第三方运行时**：纯 Win32 API + GDI+（Windows 自带），C++/WinRT 头文件来自 Windows SDK，编译为单个 `DynamicIsland.exe`，不依赖 .NET / Electron / Qt。
2. **低存在感**：屏幕顶部的一个小胶囊；不抢焦点（`WS_EX_NOACTIVATE`）、不出现在 Alt+Tab（`WS_EX_TOOLWINDOW`）、不做输入捕获。
3. **状态单一来源**：所有持久化配置集中在 `AppSettings g_settings`（`include/app_state.h`），窗口过程、托盘、设置窗口都只读写这一个结构；磁盘/注册表一致性由 `settings.cpp` 统一负责。
4. **按需重绘**：分层窗口不参与常规 `WM_PAINT` 合成；只有"画面签名"变化或动画推进时才重绘并 `UpdateLayeredWindow`。
5. **消息不打扰**：新消息只在主胶囊右侧弹出圆形副岛；内容默认藏在悬停提示里，副岛默认常驻，点击即收起（也可选 1–10 秒自动收起），不切换窗口、不打断输入。
6. **隐私与透明边界**：微信消息通过 **Windows UI Automation**（系统无障碍 API，与读屏软件同级）读取会话列表文本；QQ 消息通过 **Windows 通知中心（toast）**读取；不注入、不挂钩、不读进程内存、不访问聊天数据库。
7. **UI 单线程 + 后台监听**：只有 UI 线程操作窗口、动画与 `g_settings`；通知监听、微信 UIA 监听各有一个后台工作线程，跨线程只通过 `PostMessage` 传递堆上的通知数据。

## 2. 分层与数据流

```text
 微信窗口 ──UI Automation──► chat_watcher 工作线程 ─┐
                                                    ├─ kMsgNotification ─► UI 线程（main.cpp）
 Windows 通知中心 ──toast──► notifications 工作线程 ─┘                         │
                                                                             ▼
                                                 AppNotification → 设置过滤 → 副岛状态
                                                                             │
┌───────────────────────────── Win32 消息循环（main.cpp） ─────────────────────────────┐
│  岛窗口过程 IslandWndProc     │   托盘回调（tray.cpp）   │  设置窗口（settings_dialog.cpp） │
└───────────────┬───────────────┴───────────┬─────────────┴──────────────┬──────────────┘
                │                           │                            │
                ▼                           ▼                            ▼
        交互与命令处理                 托盘菜单 → WM_COMMAND        pending 副本 → Apply
        （悬停 / 拖动 / 点击 / 副岛）  （settings / autostart / …）  Validate → SaveSettings
                │                           │                            │
                └───────────────┬───────────┴────────────────────────────┘
                                ▼
              island.h 应用级命令（实现在 main.cpp）
              ApplySettingsAndRefresh / ResetIslandPosition / RequestApplicationExit
                                │
          ┌─────────────────────┼──────────────────────┬──────────────────────┐
          ▼                     ▼                      ▼                      ▼
   layout（几何 / DPI）   animation（缓动）      rendering（GDI+ 绘制）    theme（调色板）
          │                     │                      │                      │
          └─────────────────────┴──────────┬───────────┴──────────────────────┘
                                           ▼
                              time_format（时间 / 日期文本）
                                           │
                                           ▼
                    per-pixel alpha ARGB 位图 → UpdateLayeredWindow
```

**一次设置变更的完整数据流：**

1. 设置窗口把控件状态写入 `m_pending`（`AppSettings` 的副本），并重绘预览卡（预览卡直接调用共享渲染器 `RenderIslandPreview()`）；
2. 点击"应用/确定"（Apply/OK）：`g_settings = m_pending` → `ValidateSettings()`（全部字段钳制到合法范围）→ `SaveSettings()`（写 HKCU 注册表，并按需增删开机自启 Run 键）；
3. `ApplySettingsAndRefresh()`：按新开关收起不允许的副岛、按需请求通知访问 → `InitIslandLayout()` 重新测量 DPI 与工作区 → `FinishIslandAnimation()` 让动画立刻落到目标状态并强制重绘 → 刷新托盘提示 → 刷新设置窗口；
4. 渲染：`FormatDisplayText(g_settings)` 生成文本 → `ComputeIslandClusterGeometry()` 生成"主胶囊 + 副岛 + 提示"的组合几何 → `GetThemePalette()` 取调色板 → GDI+ 画入 32 位 ARGB 位图 → 预乘 alpha 写入 DIB → `UpdateLayeredWindow`。

**一条消息的数据流：**

微信 UIA 工作线程或 toast 工作线程检测到新消息 → 堆分配 `AppNotification` → `PostMessage(kMsgNotification)` → UI 线程 `HandleNotificationMessage()` → 回调 `OnAppNotification()`（按设置过滤来源）→ `ShowNotificationSubIsland()`：写入副岛文本、启动该来源的弹出动画、按 `notifyPeekSeconds` 设置停留截止时间（0 = 常驻）→ `RenderIslandFrame()` 弹出圆形副岛。

## 4. 启动与退出

### 4.1 启动序列

1. `ApplyDpiAwareness()`：优先 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，旧系统退回 `SetProcessDPIAware()`；manifest 同时声明 `PerMonitorV2`；
2. `CoInitializeEx(COINIT_APARTMENTTHREADED | COINIT_DISABLE_OLE1DDE)`；
3. `CreateMutexW()` 做单实例：已存在则 `FindWindowW()` + `PostMessage(kMsgShowSettings)` 后退出；
4. `GdiplusStartup()`；
5. `LoadSettings()`：读注册表 → 旧版隐藏延迟迁移 → `ValidateSettings()` → 按 Run 键实际状态校正 `autoStart`；若开启自启则刷新 Run 键路径（应对 exe 被移动）；
6. 注册窗口类、创建 `WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` 的 `WS_POPUP` 窗口；
7. `InitIslandLayout()` / `InitIslandAnimation()` / `InitIslandRenderer()`；
8. 启动常驻定时器 content（200 ms）与 tray（20 s），按设置创建 autoHide（100 ms）定时器，渲染第一帧、显示窗口、安装托盘图标；
9. `SetNotificationCallback(&OnAppNotification)` → `InitNotifications(g_hwnd)`（toast 工作线程）→ `InitChatWatcher(g_hwnd)`（微信 UIA 工作线程）；
10. 命令行含 `--settings` 时打开设置窗口；进入 `GetMessage` 消息循环。

两个监听工作线程都是可失败的：WinRT / UIA 调用异常时记录状态并退避重试；退出时由主窗口销毁路径显式关闭并 join（另有 `atexit` 兜底，避免 joinable 线程在 CRT 退出时触发 terminate）。

### 4.2 退出

托盘「退出」或内部 `RequestApplicationExit()` → `PostMessage(kMsgRequestExit)` → `DestroyWindow()` → `WM_DESTROY`：KillTimer、停止动画、`ShutdownNotifications()`、`ShutdownChatWatcher()`、`CloseSettingsDialog(false)`、`DestroyTrayIcon()`、`ShutdownIslandRenderer()`、`PostQuitMessage(0)` → 消息循环结束 → `GdiplusShutdown`、`CoUninitialize`、`CloseHandle(mutex)`。

`WM_ENDSESSION` 为真时先 `SaveSettings()`。

## 6. 渲染管线

### 6.1 窗口形态

- 岛是一个 `WS_EX_LAYERED` 分层窗口；一帧内容是"主胶囊 + 最多两枚圆形副岛 + 可选的悬停提示"，窗口矩形是这些元素外扩阴影 padding 后的并集（主胶囊左右 16 DIP / 上 10 DIP / 下 20 DIP；副岛四周约 10 DIP；提示四周约 12 DIP 且下方多留 10 DIP）。
- 窗口本身不接收 `WM_PAINT` 绘制（只 `ValidateRect`）；`WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，`WS_EX_TOOLWINDOW` 不进入 Alt+Tab。

### 6.2 每帧绘制步骤（`rendering.cpp`）

1. 由 `ComputeIslandClusterGeometry(hover, hide, subProgress[2], hoveredSub, tooltipVisible)` 得到组合几何；
2. `Graphics::Clear(Color(0,0,0,0))` 清空 ARGB 画布；
3. **圆形副岛**（先画，位于主胶囊阴影之下）：`DrawSubIsland()` 画同一套软阴影 + 垂直渐变 + 不透明度；圆内是从已安装微信 / QQ 可执行文件提取的 256 px 图标（按圆直径约 **62%** 居中裁切，周围保留材质与描边），提取失败时回退为品牌色圆形 + "微"/"Q" 字形；悬停时描边更亮更粗；
4. **主胶囊**：软阴影（10 层同心圆角矩形）、垂直渐变填充、1 px 描边、按宽度 / 高度自动缩字的时钟文本；
5. **悬停提示**：鼠标停在副岛上时，在胶囊下方画一条胶囊状提示（同套阴影 / 填充 / 描边），内容为"发送者：消息内容"或隐私模式下的"微信 有新消息"；
6. **预乘 alpha**：`LockBits` 读出 GDI+ 非预乘 ARGB，逐像素乘 alpha 写入 `CreateDIBSection` 的 DIB，满足 `AC_SRC_ALPHA`；
7. `UpdateLayeredWindow(...)` 一次提交整帧。

### 6.3 设置窗口预览

设置窗口的预览卡不再自己画迷你胶囊，而是调用与真实岛完全相同的 `RenderIslandPreview()`：同样的阴影、渐变、描边、不透明度与文字排版，按主胶囊的**实际 DPI 缩放尺寸**绘制在预览卡中央，并在卡片右上角标注"实际大小"（空间不足时随窗口整体缩小）。

### 6.4 优化

- **帧签名缓存**：`RenderSignature` 记录窗口 / 胶囊矩形、两枚副岛矩形、提示矩形、DPI、颜色、透明度、字号、粗体、时钟文本、副岛文本、悬停索引、提示可见性；签名不变时 `RenderIslandFrame(false)` 直接返回。
- **表面复用 / 字体缓存 / 调色板缓存**：同 v5.1。
- **图标缓存**：真实应用图标按来源缓存为 `Gdiplus::Bitmap`，只在首次绘制时从 exe 提取。

## 7. 动画模型

动画维护四个归一化进度（0～1），几何全部由进度实时推导：

| 进度 | 目标 | 时长 | 缓动 | 效果 |
| --- | --- | --- | --- | --- |
| `hoverProgress` | `SetIslandHoverTarget()` | 170 ms | EaseOutCubic | 主胶囊水平居中、向下扩展到 1.08 倍 |
| `hideProgress` | `SetIslandHiddenTarget()` | 260 ms | EaseInOutCubic | 整个组合滑出工作区上边缘 |
| `subProgress[0]`（微信） | `SetSubIslandTarget(0, …)` | 弹出 220 ms / 收起 180 ms | EaseOutCubic | 圆形副岛的直径、间距、位置按进度从 0 长到满 |
| `subProgress[1]`（QQ） | `SetSubIslandTarget(1, …)` | 同上 | EaseOutCubic | 同上 |

**整体居中（centre preservation）**：设主胶囊宽 `W`、高 `H`、副岛间距 `gap`、第 i 枚副岛进度 `p_i`，则

- 组合总宽 `clusterWidth = W + Σ (gap + H) × p_i`；
- 组合左边界 `left = restingCenterX - clusterWidth / 2`，主胶囊从 `left` 开始，副岛依次从 `capsule.right` 向右排；
- 因此主胶囊 + 最右副岛的中点在任意时刻都等于原来的休息中心 `restingCenterX`（仅当组合会超出工作区时，整体做水平平移以避免出屏）。

副岛默认**常驻**：`s_subDeadline[i] == 0` 表示没有到期时间，副岛一直显示，直到用户点击它（打开应用后收起）、关闭总开关或对应来源、或在设置里变更后应用。只有把 `NotifyPeekSeconds` 设为 1–10 才会设置截止时间（`now + 秒数`）；此时 `kTimerNotificationDismiss`（250 ms）才运行，副岛被悬停时截止时间被不断延后（等效暂停收起），到点调用 `SetSubIslandTarget(i,false)`。

## 8. 布局与 DPI

### 8.1 胶囊尺寸（DIP，96 DPI 基准）

| 项目 | Small | Medium（默认） | Large |
| --- | --- | --- | --- |
| 胶囊宽 | 120 | 150 | 180 |
| 胶囊高 | 24 | 28 | 32 |

其他布局常量：顶部外边距 6 DIP、左右预设边距 12 DIP、悬停最大放大 1.08、触发区在胶囊外再扩 10 DIP。

### 8.2 副岛几何

- 圆形副岛直径 = 主胶囊当前高度（跟随尺寸与悬停进度），间距 `kSubIslandGapDip = 8 DIP`；
- 最多两枚，索引固定：0 = 微信（内）、1 = QQ（外）；
- 悬停提示宽 `300 DIP`、高 `34 DIP`，位于主胶囊下方、以悬停副岛的水平中心对齐；
- 触发区（自动隐藏 / 唤出判断）在休息胶囊基础上右侧多留两枚副岛宽度、下方多留提示高度。

### 8.3 DPI 处理

- 进程声明 **Per-Monitor V2**（manifest + 运行时 API 双保险）；
- `InitIslandLayout()` 用 `GetDpiForWindow()`（缺失时退回 `GetDeviceCaps(LOGPIXELSX)`）记录 DPI，`ScaleDip()` 通过 `MulDiv(dip, dpi, 96)` 转物理像素；
- `WM_DPICHANGED` / `WM_DISPLAYCHANGE` / `WM_SETTINGCHANGE(SPI_SETWORKAREA)` 时重新初始化布局、动画落到目标并重绘。

### 8.4 位置模型与点击

- `IslandPosition`：`LEFT` / `CENTER` / `RIGHT` / `CUSTOM`；拖动达到 4 像素阈值写入 `CUSTOM` 与物理像素坐标并保存；
- 左键单击主胶囊：打开设置窗口；拖动主胶囊：移动位置；右键：不做任何操作；
- 左键单击副岛：把微信 / QQ 窗口带到前台（最小化先恢复），并收起该副岛；悬停副岛：显示提示（若启用了自动收起，悬停会暂停计时）；
- 副岛可见期间，`UpdateAutoHide()` 直接重置自动隐藏计时，避免消息提示被隐藏。

## 9. 设置与持久化

### 9.1 内存模型

`AppSettings` 是唯一结构（默认值见 `app_state.h`）：

- 时间/日期：`use24Hour`、`showSeconds`、`showAmPm`、`showDate`、`showYear`、`showWeekday`、`dateFormat`；
- 外观：`theme`、`windowSize`、`position`、`customX/Y`、`fontSize`、`boldFont`、`opacity`；
- 行为：`autoHide`、`hideDelaySeconds`、`hideOnFullscreen`、`autoStart`；
- 通知（v5.2）：`notifyEnable`、`notifyShowContent`、`notifyWeChat`、`notifyQQ`、`notifyPeekSeconds`（0–10；0 = 常驻（默认），1–10 = 自动收起秒数）。

### 9.2 读写与迁移

- `LoadSettings()` 打开 `HKCU\SOFTWARE\DynamicIsland` 逐项读取；`ValidateSettings()` 钳制全部字段（含 `notifyPeekSeconds` 0–10）；
- **旧版迁移**：`SettingsVersion < 2` 时合并旧的 `HideDelayMinutes` + `HideDelaySeconds` 为总秒数；`SettingsVersion` 保持 2，v5.2 新增的 `Notify*` 缺失时使用默认值；v5.2.1 起 `NotifyPeekSeconds` 默认 0（常驻），已有安装保留已保存的值，改成 0 即恢复常驻；
- `SaveSettings()` 写全部 DWORD 并同步 Run 键；启动时以 Run 键实际存在与否校正 `autoStart`，若存在则刷新为当前 exe 路径。

| 值 | 默认 | 含义 |
| --- | --- | --- |

| `NotifyShowContent` | 1 | 是否在悬停提示里显示发送者 / 内容 |

| `NotifyQQ` | 1 | QQ 来源开关 |

- **数据流**：控件修改 `m_pending`，预览卡用 `RenderIslandPreview()` 实时反映未保存的外观；"应用/确定"才执行 `ApplyPending()`：`g_settings = m_pending` → `ValidateSettings` → `SaveSettings` → `ApplySettingsAndRefresh`；
- **重绘**：持久 ARGB 位图/DIB；重绘请求合并为 posted `WM_APP+100`，每个消息循环最多绘制一次；只重画脏矩形（`SetClip`）并只预乘脏区；拖动标题栏只移动窗口；1 秒预览定时器只在格式化文本变化时重画预览卡，并在通知授权状态变化时重画通知卡；全窗阴影绘制改为只在透明 padding 区域裁剪绘制，源码注释记录全窗重绘约从 350 ms 降到 29 ms（150% DPI）；
- **交互**：拖动标题栏移动并钳制在工作区；取消 / X / Esc 丢弃修改关闭；Enter 等同确定；"重置位置"与"开机自启"是 pending 修改，"系统时间设置"立即打开控制面板；窗口 modeless，绝不 `PostQuitMessage`。

## 13. 消息提醒管线

### 13.1 两条来源通道

| 来源 | 获取方式 | 依赖 | 失败表现 |
| --- | --- | --- | --- |
| 微信 | Windows **UI Automation**：轮询微信主窗口的会话列表（自动化 ID `session_list`），读取每个会话项的无障碍名称文本 | 微信 4.x（`Weixin.exe` 等）正在运行（最小化到托盘也可以）；UI 树结构未变 | 收不到微信副岛 |
| QQ | Windows **通知中心 toast**：`UserNotificationListener` 轮询新通知 | QQ 在自身设置开启通知；Windows 允许 QQ 通知；本程序获得通知访问授权 | 收不到 QQ 副岛 |

### 13.2 微信 UIA 监听（chat_watcher.cpp）

- 后台工作线程初始化 COM（MTA）→ `CoCreateInstance(__uuidof(CUIAutomation))`；
- 每约 1 秒枚举顶层窗口找微信主窗口（进程可执行名为 `Weixin.exe` / `WeChat.exe` / `WeixinApp.exe`，窗口类名含 `QWindowIcon`），再以 `session_list` 自动化 ID 找会话列表并缓存；
- 每个会话项的无障碍名称按行解析：第一行 = 会话标题；"已置顶 / 消息免打扰"标记**可能出现在预览 / 时间之前或之后**，解析时逐行收集并置位 `pinned` / `muted`；末尾 = 时间（`HH:mm` / 昨天 / 星期X / MM/DD），其余行 = 最后一条消息预览；
- 首次快照只建立基线不提醒；之后若某会话的预览 / 时间变化、未被过滤规则跳过、且满足"当前会话规则"（见 13.3）、时间为今天（或该行跳到最顶部），则生成一条 `AppNotification`（来源微信、标题为会话名、正文为预览，截断 200 字符）并 `PostMessage(kMsgNotification)`；
- 微信窗口消失 / 重建时释放缓存并重置快照，避免误报；`DSH_ISLAND_DEBUG` 环境变量可打开 UTF-8 调试日志（`chat-watcher.log`），默认不写文件；日志会记录种子会话的 `muted` / `ignored` 标记，以及 "skip new row / skip changed (muted/official)"、"skip active chat (wechat foreground)" 的跳过原因。

### 13.3 提醒范围过滤与当前会话规则（v5.2.2 起）

**微信（会话列表解析 + 跳过规则）**：构造 `SessionItem` 时记录 `muted`，`IsIgnoredSession(item) = item.muted || IsIgnoredSessionTitle(item.title)`。命中以下任一条件的会话不会弹出副岛：

- 会话带"消息免打扰"标记（含免打扰群聊）——即使它的预览 / 时间发生变化也只记录跳过；
- 会话标题包含：`公众号`、`订阅号`、`服务号`；
- 会话标题等于：`订阅号消息`、`折叠的群聊`、`折叠群聊`、`服务通知`、`微信支付`、`微信团队`、`微信运动`、`微信收款助手`、`微信收款商业版`、`腾讯新闻`、`QQ邮箱提醒`、`QQ邮箱`。

因此只有普通好友会话和**未开启免打扰**的群聊会触发圆形副岛。过滤发生在"新会话行"和"已有会话变化"两条路径上，且与"当前选中会话跳过"相互独立。

**QQ（toast 文本关键字过滤）**：QQ 只能拿到 toast 文本（标题 + 正文），`main.cpp` 的 `IsIgnoredQqNotification()` 会对拼接后的文本做关键字匹配，命中即忽略：

`订阅号`、`公众号`、`服务号`、`QQ看点`、`看点`、`QQ空间`、`空间动态`、`腾讯新闻`、`腾讯视频`、`QQ邮箱`、`邮箱提醒`、`游戏中心`、`直播提醒`、`会员活动`、`活动推送`。

**当前会话跳过规则（v5.2.3）**：过滤规则之后，还要判断"是否跳过当前打开的会话"：

- `IsAlwaysNotifySessionTitle(title)`：标题为 `文件传输助手` 的会话**始终提醒**，即使它正是当前打开的会话（常用于接收手机发来的文件）；
- 其他会话：只有当 `IsWeChatForeground()` 为真（前台窗口的进程是 `Weixin.exe` / `WeChat.exe` / `WeixinApp.exe`，即用户正看着微信）时才跳过当前选中的会话；微信最小化 / 在后台时，当前会话的新消息也会提醒；
- "新会话行"路径同样应用该条件：只有顶部新行且（未选中 / 文件传输助手 / 微信不在前台）并且时间为今天时才提醒。

**副作用**：从电脑向文件传输助手发送文件 / 消息（手机传文件）也会触发提醒——会话列表里"收到"与"发出"的变化看起来相同，程序无法区分方向。

**限制**：QQ 免打扰群聊是否提醒取决于 QQ 自身是否推送 toast（程序无法从 toast 判断免打扰状态）；微信过滤基于会话列表可访问的标题与"消息免打扰"标记，极少数名称特殊的普通会话可能被误判。

### 13.4 QQ toast 监听（notifications.cpp）

- C++/WinRT 后台线程每约 800 ms 轮询 `UserNotificationListener.GetNotificationsAsync(Toast)`；启动时先取"最大通知 Id"作为基线，历史通知不会重放；
- 按 AppUserModelId / 显示名分类：微信类（`weixin/wechat/微信`，用于仍会发 toast 的旧版微信）、QQ 类（AUMID 或显示名恰为 `QQ`、`...\QQNT\QQ.exe`、`...\Tencent\QQ\Bin\QQ.exe`）；并显式排除 QQ 音乐 / QQ 浏览器 / 腾讯视频 / QQLive 等其他腾讯产品；
- 首次访问状态为 `Unspecified` 时自动 `RequestAccessAsync()`；设置窗口可查询状态并再次发起授权。

### 13.5 UI 线程与副岛生命周期

- 工作线程只 `PostMessage(kMsgNotification)`（微信侧的提醒范围过滤、当前会话前台判断都在工作线程完成，只有真正要提醒的消息才会投递）；UI 线程 `HandleNotificationMessage()` 调用注册回调后立即 `delete` 掉堆数据；
- 回调 `OnAppNotification()` 按 `notifyEnable` / `notifyWeChat` / `notifyQQ` 过滤；QQ 还要先过 `IsIgnoredQqNotification()` 关键字过滤（官方推送不提醒），然后 `ShowNotificationSubIsland()`：写入副岛文本（微信 / QQ 各自缓存最后一次内容）、启动该来源的副岛动画；`notifyPeekSeconds > 0` 时给该来源设置 `now + 秒数` 的截止时间（否则截止时间为 0 = 常驻），并只在存在计时副岛时启动 250 ms 检查定时器；
- 悬停计时中的副岛会持续延后截止时间；点击副岛时 `ActivateSourceApp()`（`EnumWindows` 定位对应进程的可见/隐藏主窗口，`ShowWindow` 恢复，`SetForegroundWindow` 失败时回退 `SwitchToThisWindow`）并收起；
- 点击副岛、关闭总开关 / 对应来源、或应用设置时，会清零截止时间并收起相关副岛；副岛可见期间自动隐藏暂停。

### 13.6 隐私

- 消息文本只存在于工作线程 → UI 线程的内存载荷、渲染器里的两枚副岛文本缓存中，用完 / 被覆盖即释放，不写入注册表、配置文件或磁盘；
- "显示内容"关闭时，副岛不显示任何消息文本，悬停提示只显示"微信 有新消息 / QQ 有新消息"；
- 程序不读取微信 / QQ 进程内存、不注入、不挂钩、不访问聊天数据库；微信通道只读取 Windows 无障碍树公开的文本。

## 14. 关键设计决策

| 决策 | 选择 | 理由 / 代价 |
| --- | --- | --- |
| 窗口合成方式 | 分层窗口 + `UpdateLayeredWindow` | 逐像素 alpha 与抗锯齿圆角 / 软阴影；代价是每帧自己预乘与整窗提交 |
| 绘图库 | GDI+ | Windows 自带；代价是 CPU 绘制，但岛面积很小 |
| 设置界面 | 全自绘窗口 | 跟随主题 / DPI，可做出等高双列与像素级一致的预览；代价是代码量大 |
| 微信消息来源 | UI Automation 读会话列表 | 微信 4.x 不发 toast，无法用通知中心；UIA 是系统公开无障碍接口，不注入不读内存；代价是依赖微信 UI 结构与进程运行 |
| QQ 消息来源 | Windows 通知（toast） | QQNT 不暴露 UIA 树，toast 是唯一公开通道；代价是用户必须开启 QQ 与 Windows 通知 |
| 副岛呈现 | 主胶囊右侧圆形副岛，最多两枚 | 不遮挡时间文字、视觉上与胶囊同材质；代价是需要组合几何与整体居中处理 |
| 整体居中 | 组合总宽按进度实时计算并居中 | 副岛出现 / 消失时视觉中心不跳动，动画更自然 |
| 副岛停留 | 默认常驻，可选 1–10 秒自动收起（v5.2.1） | 消息不会被错过，点击副岛打开应用即收起；代价是副岛会一直占用主胶囊右侧空间，直到用户处理或关闭来源 |
| 提醒范围过滤 | 微信按会话标题 + 免打扰标记跳过，QQ 按 toast 关键字跳过（v5.2.2） | 只让真正的聊天消息打扰用户，公众号 / 系统 / 官方推送不弹副岛；代价是关键字规则可能误判极少数特殊名称 |
| 当前会话提醒 | 文件传输助手始终提醒；其他会话仅在微信前台时跳过当前会话（v5.2.3） | 避免在微信里打字时自我提醒，同时离开微信后不漏消息；代价是电脑→手机传文件也会提醒 |
| 消息内容呈现 | 默认只在悬停提示显示 | 不主动暴露聊天内容，降低公共场合的隐私风险；代价是需要一次悬停才能看到内容 |
| 设置窗口重绘 | 脏矩形 + 合并绘制 | 只重画变化区域；代价是维护脏区计算与持久表面 |
| 反作弊策略 | 不规避、纯外部窗口 + 公开接口 | 不注入、不挂钩、不读内存；提供全屏隐藏，无法保证反作弊系统不误判 |
| 分发方式 | 单 exe，无安装器 | 复制即用；卸载用 `clean.ps1` |

## 16. 已知限制与可扩展点

- 微信通道依赖微信 UI 的 UI Automation 结构：微信大版本更新可能改变自动化 ID / 文本布局，需要适配；只能读到会话列表最后一条预览，读不到历史消息；当前打开的会话只在微信处于前台窗口时才跳过，文件传输助手始终提醒（v5.2.3）；
- 微信客户端未运行（完全退出）时无法读取会话列表；QQ 未开启系统通知 / 未授权通知访问时收不到提醒；
- 提醒范围过滤（v5.2.2）基于可访问文本：微信按会话标题 + "消息免打扰"标记判断，QQ 按 toast 标题 / 正文关键字判断；极少数名称特殊的普通会话可能被误判，QQ 免打扰群聊是否提醒取决于 QQ 是否仍推送 toast；从电脑向文件传输助手发送内容也会提醒（v5.2.3 的已知副作用）；
- 消息内容默认只在悬停提示中出现，且只在内存中短暂保留，不写盘；
- 副岛横向排布在工作区边缘会被整体平移以避免出屏，此时"整体居中"让位于不出屏；副岛默认常驻，会一直显示到用户点击或关闭来源，若希望自动清理可在设置里启用 1–10 秒自动收起；
- 预设位置仍基于主显示器；自定义位置保存物理像素，DPI 变化后不按比例迁移；
- 界面文案均为中文（设置窗口、关于对话框、托盘菜单），未做多语言；
- 托盘 tooltip 每 20 秒刷新，最多滞后 20 秒；主题兜底轮询 5 秒；
- 无自动更新、无代码签名；反作弊兼容性只做行为声明，不作保证。
